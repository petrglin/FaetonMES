# Базовый сайт

Next.js 16.3.8 (App Router), React 19.3.0, TypeScript и Tailwind CSS 4.3.3.
Без внешнего backend, базы данных, UI-библиотек и внешних шрифтов. Главная страница — служебная заглушка; дизайн будет добавлен позже.

## Запуск на Mac

Нужен Node.js 20.9+; рекомендуется Node.js 24 LTS (версия указана в .nvmrc).
Из папки проекта:

```sh
npm ci
npm run dev
```

Открыть http://localhost:3000. Сервер слушает только локальный интерфейс. Для остановки — Ctrl+C.
Если порт занят: npm run dev -- --port 3001.

## Проверки и production

```sh
npm run lint
npm run typecheck
npm run build
npm start
```

## Структура

- src/app — страницы, общий layout и глобальные стили.
- src/components — будущие переиспользуемые компоненты.
- src/lib — общая логика и вспомогательные функции.
- public — статические файлы.

## Виртуальная фабрика

Кнопка «Виртуальная фабрика» открывает `/mini-factory`. Фабрика занимает центральную область во всю ширину; хедер и футер принадлежат сайту. Исходный HTML загружается во фрейме, сохраняет собственную изоляцию скриптов и доступ к полноэкранному режиму. Только для встраивания убираются поля его внешней оболочки.

На этом Mac в `.env.local` задан `FACTORY_DEMO_SOURCE_DIR` — папка `/Users/alexshmakov/Documents/Codex/2026-10-06/pyf/outputs`, содержащая `factory-demo.html` и `resources/`. В режиме `npm run dev` сайт читает файлы непосредственно из этой папки при каждом запросе. Фабрику редактируем там же, где и раньше; для просмотра правок обновляем страницу. При смене пути перезапускаем dev-сервер.

`npm run build` автоматически выполняет `factory:sync`, обновляя переносимый снимок в `vendor/factory-demo/`. В production используется только этот снимок, без зависимости от пути на Mac. На другом компьютере без исходной папки оставьте `FACTORY_DEMO_SOURCE_DIR` пустым: сайт будет использовать комплектную версию. `vendor/factory-demo/` не редактировать вручную. Для отдельного просмотра того же источника доступен `/factory-demo/factory-demo.html`.

Демо сохраняет существующие внешние зависимости (включая Three.js с CDN), поэтому загрузка 3D-сцены требует интернета. Новых зависимостей для встраивания не добавлено. Проверка источника, обновлений и ограничения доступа: `node --test tests/factory-source.test.mjs`.

Серверная отправка запросов на расчёт реализована через POST /api/quote в Next.js. База данных не используется. Секреты SMTP хранятся в .env.local (игнорируется Git) и не передаются в клиентские компоненты.

## Локальный Git

На этом Mac системный git требует отсутствующие Apple Command Line Tools. Поэтому в .tools/git установлен автономный Git 2.53.0 из пакета dugite; он не является зависимостью сайта и исключён из репозитория.

В этой копии проекта доступны команды:

```sh
npm run git -- status
npm run git -- log --oneline
npm run git -- add .
npm run git -- commit -m "Описание изменений"
```

Репозиторий локальный, ветка main, удалённый репозиторий не подключён. При отсутствии настроенного автора используется локальное имя Local Developer и email developer@localhost. Перед следующими коммитами можно задать свои данные через npm run git -- config user.name "Имя" и npm run git -- config user.email "email".

Папка .tools/git не переносится через Git. На другом Mac используйте установленный git; при необходимости стандартный Git доступен после установки Apple Command Line Tools командой xcode-select --install. Для npm-команды git в новой копии потребуется автономный Git в .tools/git.

## Результаты проверки

Проверены npm run lint, npm run typecheck и npm run build; главная страница открывается в браузере.

В npm run dev включён WATCHPACK_POLLING=true: на этом Mac нативный watcher возвращал EMFILE. Polling позволяет отслеживать изменения без этой ошибки; при необходимости на другой машине можно убрать переменную из команды dev.


Документация Next.js: https://nextjs.org/docs/app/getting-started/installation

## Отправка запросов на расчёт

Получатель заявок: **olvenn@mail.ru**. Сайт отправляет письмо сам через SMTP отдельного почтового ящика. Ответ на такое письмо направляется клиенту, указанному в форме.

В файле .env.local укажите:

- SMTP_HOST — сервер исходящей почты отправителя.
- SMTP_PORT — 465 (TLS) или 587 (STARTTLS).
- SMTP_USER — логин отправляющего ящика.
- SMTP_PASSWORD — пароль приложения/SMTP этого ящика.
- SMTP_FROM — адрес отправителя, если отличается от SMTP_USER.

Шаблон без секретов — .env.example. После заполнения перезапустите npm run dev -- --webpack. Пароль не хранить в Git и не передавать через чат.

Письмо содержит контакты клиента, вариант внедрения, выбранные модули и комментарий. При отсутствии SMTP-настроек API возвращает 503; при сбое отправки — 502. Успех отображается только после подтверждения приёма получателя почтовым сервером. Файл запроса можно скачать и без SMTP.

Проверки данных, содержания письма и обработчика без реальной отправки:

```sh
node --test tests/quote-request.test.mjs tests/quote-api.test.mjs
```

Для этих тестов требуется Node.js 24 (используется встроенная поддержка TypeScript).
