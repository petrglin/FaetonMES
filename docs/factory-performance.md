# Производительность виртуальной фабрики

Проверено 8 ноября 2026 года. Изменения внесены в единый исходник `factory-demo.html` в папке, заданной `FACTORY_DEMO_SOURCE_DIR`. Сайт читает его напрямую при разработке; `npm run factory:sync` и `npm run build` обновляют комплектный снимок в `vendor/factory-demo`.

## Что влияло на плавность

Главная нагрузка была внутри 3D-сцены: тысячи отдельных объектов и команд WebGL, повторный пересчёт мировых матриц для подсветки даже без указателя над сценой, опрос CSS и запись значений элементов управления в каждом кадре. На Retina рендер выполнялся с коэффициентом 2, то есть на каждый CSS-пиксель приходилось четыре пикселя буфера. Скорость загрузки CDN влияет на первый запуск, но не объясняет постоянные затраты на каждый кадр уже загруженной сцены.

## Внесённые изменения

- 1749 неподвижных элементов конвейеров объединены в 11 групп `InstancedMesh` без изменения их геометрии и расположения. Подход использует штатный механизм [Three.js InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html), сокращающий число команд отрисовки.
- Повторяющиеся элементы оборудования тоже рисуются группами. Простые прямоугольные детали используют единичный параллелепипед с точным преобразованием размеров и положения. Текстурированные, прозрачные и неподходящие геометрии остаются отдельными. Материалы группируются по идентичности объекта: независимые сигналы и индикаторы не получают общий изменяемый материал.
- Исходные объекты оборудования сохранены для механики и выбора мышью на слое 31. Луч выбора учитывает этот слой, камера — нет. Перед кадром преобразования и видимость передаются в экземпляры. При создании архивной копии палеты восстанавливается её обычный слой отрисовки.
- Полный пересчёт матриц для подсветки без курсора удалён; поиск объекта при наведении выполняется до 30 раз в секунду, а подсветка продолжает анимироваться каждый кадр. Нажатие обрабатывается сразу.
- Чтение цветов CSS ограничено четырьмя разами в секунду; значения ползунков и подписей записываются только при изменении.
- Коэффициент рендера ограничен 1,5 вместо 2. На Retina это сокращает число пикселей буфера примерно на 44%. Сглаживание сохранено.
- В скрытой вкладке расчёт и отрисовка пропускаются. После возврата временная база сбрасывается, чтобы не было скачка сцены.

## Замеры и границы проверки

Снимки диагностических показателей в скрытой проверочной вкладке IAB (WebKit), с областью сцены около 1280 × 396 CSS-пикселей:

| Показатель | До | После |
| --- | ---: | ---: |
| Частота кадров | около 7,4 FPS | около 29–34 FPS |
| Среднее время JavaScript и отправки команд на кадр | около 133 мс | около 15 мс |
| Команды основного прохода рендера | около 5580 | около 1400–1700 |
| Коэффициент пикселей | 2 | 1,5 |

Это наблюдения в разных состояниях работающей демонстрации, а не синхронный GPU-бенчмарк одинакового кадра. Они не гарантируют такую же частоту в Chrome или на другом устройстве. Размер окна, разрешение дисплея, GPU, энергосбережение, состояние процесса и фоновые приложения продолжают влиять на FPS. Метрика CPU не является измерением времени выполнения GPU.

Для последующих замеров JSON обновляется раз в секунду в `data-factory-performance` корневого элемента `#furniture-line` внутри сцены. В интерфейсе дополнительная техническая панель не показывается.

## Регрессия

Локальная проверка использовала реальную библиотеку Three.js 0.160.0 и подставной renderer для детерминированного сравнения исходной и новой версии. Состояния на десяти контрольных точках за 1000 секунд модельного времени совпали, включая выпуск деталей, остановку сверления, упаковки и отгрузку. Также совпали результаты повторного запуска, границы сцены и выбор объектов лучом в 12 контрольных направлениях. Этот тест проверяет механику и геометрию, а не реальную GPU-частоту кадров.

В настоящем браузере проверены загрузка сцены, отсутствие ошибок рендера, пауза/продолжение и переключение верхнего/перспективного вида. Локальные материалы измерений и резервная копия до изменений сохранены в `work/factory-performance/` и не включаются в Git или сборку.

Проверки источника проходят командой `node --test tests/factory-source.test.mjs`. Для production-проверки в этом окружении использована команда `npm run build -- --webpack`: Turbopack останавливался на ограничении создания вспомогательного локального порта при обработке CSS, независимо от изменений фабрики.

## Переход к отгрузке и перспектива

При «К отгрузке» создавались 128 моделей деталей, включая 112 уже упакованных и невидимых. Теперь отрисовка создаёт только 16 видимых деталей; все исходные записи остаются в модели производства. Геометрия сверления повторно используется для одинаковых размеров и не уничтожается при удалении отдельной детали. Окружности отверстий используют 32 сегмента; малые 3D-этикетки — текстуры вдвое меньшего линейного разрешения. Исходное разрешение этикеток для документов и всплывающих просмотров сохранено.

В локальном тесте с реальной геометрией Three.js и подставным renderer подготовка сократилась с 7,9–9,4 секунды примерно до 0,25 секунды; в браузере обработчик измерен в 355 мс. Начальное состояние отгрузки и состояние после 180 секунд моделирования совпадают с исходной версией.

«Перспектива» сохраняет углы камеры, но исключает невидимые области выбора и вспомогательные поля маршрутов из подгонки. Проекция центрируется и занимает до 96% ограничивающего размера окна, сохраняя небольшой запас без обрезания. Проверены широкие, стандартные и узкие области просмотра. Правки применены к 16 распакованным мебельным HTML-версиям в исходной папке (русские/английские, печатные, Mac, Windows, Localhost и Europe); ранее созданные ZIP-архивы не пересобирались.

Проверки подгонки, повторного использования геометрии и подписи: `node --test tests/factory-view.test.mjs`. Подготовка по кнопке диагностируется через `data-shipping-preparation-ms` на `#furniture-line`.
